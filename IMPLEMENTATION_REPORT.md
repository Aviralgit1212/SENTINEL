# Implementation Report — Sentinel Privacy Security

## Summary

The supplied AI-GUARDIAN project was preserved and modified in a separate working copy. The final release retains its FastAPI backend, Chrome extension, dashboard, SQLite audit/reviewer flow, existing scanners/redactors, and optional Corsair sidecar. It adds privacy-focused lifecycle controls, scan coverage/outcome reporting, explicit cache choices, tested custom detectors, and selective PDF/DOCX metadata handling.

## Changes by workstream

- **Privacy and payload lifecycle:** `backend/release_store.py`, `backend/release_api.py`, and `backend/main.py` use bounded process-memory retention, 20-minute idle expiry, one-time release credentials, explicit unavailable-after-restart behavior, and reviewer-authenticated loopback clearing. Persistent audit history remains separate; original bytes/text are not written to the audit DB.
- **Limits and scan outcomes:** uploads are capped at 25 MiB, multipart buffering is bounded with a two-upload concurrency limit, supported formats are PDF/DOCX/PNG/JPG/JPEG, and XLSX is rejected. Extraction, OCR, coverage, policy, and redaction failures yield explicit `INCOMPLETE` or blocked-with-error outcomes rather than clean ALLOW.
- **PDF/OCR:** PDF analysis records page-level selectable-text/OCR coverage and caps OCR at 15 pages. Missing/low OCR confidence and XMP metadata that cannot be reviewed make coverage incomplete. Sensitive OCR text in a PDF image layer is blocked as incomplete because this release does not perform pixel-level PDF redaction. Standard PDF info-dictionary fields are scanned transiently and only sensitive spans are redacted; unrelated standard fields are retained and checked after output generation.
- **DOCX/images:** DOCX paragraphs, tables, headers, footers, and supported core properties are scanned. Sensitive property spans are selectively redacted and rechecked. Unsupported comments, tracked changes, media, text boxes, footnotes/endnotes, external relationships, and data-bearing custom XML are surfaced as incomplete. Empty default bibliography custom XML is recognized as non-data-bearing. Image OCR must have readable text and adequate confidence; sensitive image spans use existing coordinate-aware pixel redaction and post-OCR verification.
- **Detection and policy:** `backend/scanner/scanner.py`, `policy/policy.json`, and risk tests cover existing Presidio categories plus synthetic Aadhaar candidates with Verhoeff validation and cautious OCR-confusable normalization, PAN, IFSC, and limited credential-like tokens. Positive/negative examples are synthetic. These are limited detectors, not authoritative validators.
- **Cache:** `backend/cache_store.py` stores seven-day SHA-256-keyed reports in separate `privacy_cache.db`, and a dynamic hash of scanning/policy/extraction/redaction sources invalidates incompatible entries. The extension offers explicit reuse/rescan; re-scan updates only the cached report while audit events remain. Cache reports reject raw-payload fields. Cached REDACT decisions are not reused; the user is routed to a fresh scan so output can be generated and verified again.
- **Extension/Gemini:** `extension/content.js`, `extension/background.js`, and `extension/manifest.json` include Gemini text selectors, generic file-input/drop interception, a static dismissible once-per-tab-session unsupported-site banner, honest backend/interception failure notices, and no-Gmail behavior. Scan responses are no longer written to developer consoles. Chrome-wide matching is disclosed because the unsupported-site notice requires page injection; grant the broad site permission only if acceptable.
- **Dashboard/audit:** the existing dashboard is extended, not replaced. Events distinguish manual/report-only from extension-origin/enforced scans and show file type/size/hash, decision, report source/time, coverage, safe detector metadata, and redaction verification scope. Cache clear preserves audit history. Existing reviewer actions remain event-specific and audit-recorded.
- **Backend/security:** CORS is limited to the extension origin and local dashboard development ports, with the exact scan/cache headers and cache-clear method enabled. Reviewer and release operations remain authenticated as implemented; release operations require loopback access. CORS is not authentication, and a locally forged Origin is not a trusted identity.
- **Packaging/docs:** setup instructions, sanitized backend and sidecar environment templates, implementation and test reports, and a clean distributable ZIP are included. Populated databases, actual environment files, generated bytecode and build/cache artifacts are excluded.

## Known limitations

- No Chrome/Gemini live end-to-end browser session was available, so selector stability, actual DOM interception, upload behavior, and visible notice interactions are **not verified in a live browser**.
- Scanned PDF image content can be OCR-inspected, but sensitive image-layer content is blocked as `INCOMPLETE`; pixel-level PDF redaction is not supported. PDF XMP metadata is not parsed/redacted; its presence is reported as incomplete. Standard PDF info-dictionary metadata is supported.
- DOCX secondary layers listed in coverage remain unsupported and cause `INCOMPLETE`; unknown content is not silently treated as clean.
- Cached `REDACT` reports require a full fresh scan instead of replaying mappings.
- Manual `/scan` and `/scan-file` calls provide a report/recommendation, not protection of an unrelated website submission.
- Site selectors and content-script interception can break when a platform changes its DOM or uses a custom flow. A notice is not proof of enforcement.
- Four FastAPI lifecycle deprecation warnings remain (`on_event` handlers); they do not fail tests.
- The optional Corsair/Slack sidecar was not started or tested against an external workspace; `test_corsair.ts` can send a real Slack message and was intentionally not run.
